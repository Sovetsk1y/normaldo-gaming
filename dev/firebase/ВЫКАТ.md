# Выкат серверной части

Проект: **`normaldo-game`** (см. `.firebaserc`), регион функций — **`europe-west1`**
(`setGlobalOptions` в `functions/src/index.ts`, строка 10).

Всё ниже выполняется из папки `dev/firebase`.

## Что не выкачено

Клиент уже ходит за этим, а на сервере этого нет:

* **`getProfile`** — карточка чужого игрока из таблицы лидеров;
* `MODES` / `PRIZE_MODES` — разбиение таблицы по режимам;
* починка `weeklyReset` (снимок недели);
* **индексы `ep4` и `ep5`** в `firestore.indexes.json`.

Индексы важны отдельно: `getLeaderboard` сортирует по двум полям сразу, и без
составного индекса запрос падает с `FAILED_PRECONDITION`, а функция отвечает
пятисоткой. `--only functions` файл индексов **не трогает** — их надо выкатывать
своей командой, и первыми.

## Команды по порядку

```bash
cd dev/firebase

# 0. Firebase CLI, если его нет
npm i -g firebase-tools

# 1. Вход. Откроет браузер; на машине без браузера — firebase login --no-localhost
firebase login

# 2. Проверить, что выбран тот проект
firebase use default          # -> normaldo-game
firebase projects:list

# 3. Собрать функции и убедиться, что типы сходятся.
#    npm run build сам зовёт check-indexes.mjs — он сверяет режимы в коде
#    с индексами в firestore.indexes.json и валится, если появился режим
#    без индекса.
npm ci --prefix functions
npm run build --prefix functions

# 4. ИНДЕКСЫ ПЕРВЫМИ. Они строятся асинхронно, минуты; функция, выкаченная
#    раньше готового индекса, будет отвечать пятисоткой до конца стройки.
firebase deploy --only firestore:indexes

# 5. Дождаться, пока все станут READY (или посмотреть в консоли Firestore)
firebase firestore:indexes

# 6. Правила и функции
firebase deploy --only firestore:rules
firebase deploy --only functions
```

### Только getProfile

Если нужен ровно он и ничего больше — индексов ему не надо, он читает документ
по идентификатору:

```bash
firebase deploy --only functions:getProfile
```

### Если `weeklyReset` не встал с первого раза

Расписание ему заводит Cloud Scheduler, и на новом проекте он иногда не успевает
включиться к моменту выката — деплой падает на этой одной функции. Лечится
повтором:

```bash
firebase deploy --only functions:weeklyReset
```

### Проверка после выката

```bash
firebase functions:list                       # getProfile в списке, регион europe-west1
firebase functions:log --only getProfile -n 50
```

В игре: таблица лидеров → тап по чужой строке. Карточка заполняется данными с
сервера; пока `getProfile` не выкачен, она показывает только то, что уже лежит
в строке таблицы, и молча не дополняется.

## Чего здесь сделать нельзя

В этой среде нет ни Firebase CLI, ни доступов к проекту, поэтому выкат не
проверен вживую — код собран и типы сходятся (`npm run lint --prefix functions`),
но на сервере его нет.

## Что менялось в функциях (и что из-за этого выкатывать)

`submitScore` теперь принимает и кладёт в документ игрока блок `stats` —
накопленное за всё время: съедено, забегов, лучший забег, пройдено эпизодов,
открыто скинов, взято наград книги. `getProfile` его отдаёт: без этого чужая
карточка в лидерах отвечала на «а кто это» тем же, что уже написано в строке
таблицы.

Выкатывать обе функции: `firebase deploy --only functions:submitScore,functions:getProfile`.
Индексы и правила не трогались.

Статистика появляется у игрока с ПЕРВОГО забега после выката: она уезжает
вместе с результатом, отдельного похода по сети ради неё нет. У тех, кто с тех
пор не играл, её в документе не будет, и карточка честно скажет «про него пока
не знаем» — это не ошибка выката.
