# Таблица лидеров

Соревновательный слой над одиночной аркадой. Решает три задачи:

1. **Retention** — еженедельные призы дают повод вернуться в следующий понедельник
2. **Маркер мастерства** — место в таблице — измеримый ответ на вопрос «насколько я хорош»
3. **Социальный мотиватор** — даже без друзей в игре есть «лица» соперников вокруг твоего места

---

## Контур таблицы

Лидерборд ведётся **по всем четырём режимам**, у каждого своя таблица:

| Вкладка         | Что мерит                                  | Почему сравнение честное                                    |
| --------------- | ------------------------------------------ | ----------------------------------------------------------- |
| **ЭПИЗОД 1**    | лучший забег в первом эпизоде за неделю    | дистанция у всех одна и та же — уровень и его босс            |
| **ЭПИЗОД 2**    | то же во втором                            | то же                                                         |
| **ЭПИЗОД 3**    | то же в третьем                            | то же                                                         |
| **БЕСКОНЕЧНЫЙ** | лучший забег в бесконечном режиме за неделю | сравнивается, кто уехал дальше                                |

Во всех четырёх зачёт один и тот же — **лучший забег за неделю**.

### Почему больше нет «горы пицц»

Вторая вкладка складывала пиццы за все забеги недели. Она мерила не игру, а
усидчивость: наверху оказывался не тот, кто играет лучше, а тот, кто играет
дольше — и обогнать его мастерством было нельзя в принципе, только временем.

Разбиение по режимам решает ту же задачу («разные пути к призу») честнее:
эпизод — короткая фиксированная дистанция, где выигрывает чистое прохождение,
а бесконечный — марафон, где выигрывает выносливость. Оба соревнования
настоящие, и в обоих можно выиграть игрой.

### Доступность

**Вкладка открыта ровно тогда, когда открыт её режим.** Смотреть чужие рекорды
там, куда ещё нельзя попасть, — значит видеть спойлер и не иметь возможности на
него ответить.

- **Эпизод 1** открыт всегда: с него игра и начинается
- **Эпизод N** — после того как пройден эпизод N−1 (`SaveData.episodes_done`)
- **Бесконечный** — после всей кампании

Раньше экран целиком накрывался модалкой «ЛИДЕРБОРД ЗАКРЫТ», пока не открыт
бесконечный. Таблица тогда была одна, и до конца кампании смотреть было
нечего. Теперь закрытыми бывают отдельные вкладки, и говорит об этом **замок на
самой вкладке**; по нажатию — подсказка «Сначала пройди эпизод 2».

### Что считается «закрытым забегом»

Смерть или победа над боссом в любом из четырёх режимов. Если игрок вышел из
приложения посреди забега — счёт не зачтён (как сейчас).

## Цикл — неделя

Лидерборд работает поверх **скользящей недели**:

```
Понедельник 00:00 UTC → Воскресенье 23:59 UTC → ресет
```

При ресете:
1. Снапшот недели сохраняется в `history/{week_id}` (для отображения «итоги недели» и аналитики)
2. Все рекорды недели (`mode_best` — по одному числу на режим) обнуляются
3. Призы за прошлую неделю начисляются игрокам в виде `pending_rewards` — выдаются модалкой при входе в игру

**Why UTC**: единое время на весь мир, без региональных сюрпризов. Для игрока локализуется как «Призы через 3д 14ч 22м».

## Призы

Приз показан **прямо в строке места**, в виде «доллары + жетоны». Каждая вкладка раздаёт свой пул независимо — игрок, попавший в топ нескольких режимов, получает приз за каждый.

| Место | Награда |
|-------|---------|
| 1 | 5000 $ + 10 жетонов |
| 2–3 | 2500 $ + 5 жетонов |
| 4–10 | 1000 $ + 2 жетона |
| 11–50 | 300 $ + 1 жетон |
| 51–100 | 100 $ + 1 жетон |
| 101+ | 1 жетон (утешение) |

Логика: разрыв между «топ-10» и «топ-100» ощутимый, чтобы было ради чего напрягаться, но и хвост получает жетон, чтобы не отвалиться после первой попытки.

**Игроки без ранга** (не сыграли ни одного забега за неделю в этом режиме) — не получают ничего. Это защита от инфляции наград.

## UX — где появляется

### 1. Экран смерти — превью места

Под блоком статистики (pizza count + dollars + new high score) добавляется компактный блок ранга **в одну строку** — про тот режим, который только что играли:

```
┌──────────────────────────────────┐
│ ТВОЁ МЕСТО НЕДЕЛИ                │
│ Эпизод 2        #58   ▲ +4       │
│ Тап для полного рейтинга →       │
└──────────────────────────────────┘
```

Строк было две — «Рекорд забега» и «Гора пицц», — и обе про один и тот же
бесконечный: два взгляда на один забег. Теперь у каждого режима своя таблица, и
осмысленна ровно та, куда сейчас ушёл результат.

- Слева — название режима, справа — место и дельта за этот забег
- `NEW` появляется, если в этом забеге игрок впервые попал в таблицу режима
- Тап → полный экран лидерборда с открытой вкладкой этого режима

Если игрок впервые попал в таблицу — рамка блока пульсирует зелёным.

Если **бэкенд недоступен** (оффлайн / ошибка): в месте показывается `—`, тап ведёт на полный экран с общей ошибкой «Проверь связь, попробуй позже».

### 2. Полный экран лидерборда

Вход:
- С экрана смерти — тап по строке ранга
- С главного меню — кнопка `ЛИДЕРЫ` (новый chip в Row 3, рядом с `ДОСТИЖЕНИЯ`)

```

├─────────────────────────────────────────┤

│ 🥈  2   PizzaFan       388 🍕   2500$+5ж │
│ 🥉  3   Normaldo777    367 🍕   2500$+5ж │
│     4   GreyHat        354 🍕   1000$+2ж │
│     5   Cat3000        341 🍕   1000$+2ж │
│     6   Mongoose       330 🍕   1000$+2ж │
│     7   Tony777        318 🍕   1000$+2ж │
│     8   Sushi3000      305 🍕   1000$+2ж │
│     9   Pavel99        298 🍕   1000$+2ж │
│    10   Vasil          280 🍕   1000$+2ж │
│    11   ...                              │
│    ...                                   │
│   100   Tail-Player    42 🍕    100$+1ж  │
├─────────────────────────────────────────┤
│   ►  МОЯ ПОЗИЦИЯ                        │  ← плавающая кнопка
└─────────────────────────────────────────┘
```

- Загружается и отображается **топ-100**
- Топ-3 — с медалями и яркими цветами
- Каждая строка показывает приз — игрок понимает, что получит и сколько мест ещё надо подняться до следующего тира
- Сверху — таймер до выплаты призов
- В правом нижнем углу — плавающая кнопка **«МОЯ ПОЗИЦИЯ»**:
  - Если игрок в топ-100 → скроллит к его строке и центрирует её, добавляет подсветку (`►`)
  - Если игрок ниже 100 → подгружает «окно» с сервером ±5 строк вокруг его места и заменяет нижнюю часть списка (топ-10 остаётся вверху, ниже разделитель «...», ниже — окно из ±5 строк)
  - Если игрок без ранга → кнопка не отображается; вместо строки показывается мини-баннер «Ты ещё не в таблице. Сыграй забег»
- Под вкладками — мини-блок «Прошлая неделя» в первые 24 часа после ресета: «Прошлая неделя: #12 (Рекорд), награда забрана» с подсветкой

#### Контроллы

- Свайп вверх/вниз — скролл
- Тап по вкладке — переключение режима (внутри одного экрана; список перезагружается). Тап по закрытой вкладке не переключает, а показывает подсказку, чего для неё не хватает
- Тап по «?» справа от полосы — что означает разбиение на четыре таблицы. Подсказка одна на всю полосу: четыре одинаковых знака вопроса — это не помощь, а сыпь
- Тап по любой строке — нет действия (имена не кликабельны; без друзей)

### 3. Модалка «приз получен»

При входе в игру, если есть `pending_rewards` от прошлой недели — модалка с конфетти:

```
[экран затемнён + конфетти]
"ПРОШЛАЯ НЕДЕЛЯ"
"Бесконечный — #12 место"
"+1000$  +2 жетона"
[кнопка ЗАБРАТЬ]
```

После тапа — `SaveData.add_dollars + add_tokens`, иконки летят в HUD, запись удаляется из `pending_rewards`.

Если призов несколько (по нескольким режимам) — модалки идут последовательно.

## Идентичность игрока

Сейчас в `save_data.gd` нет персонального имени — только `active_skin`. Для таблицы нужно стабильное отображаемое имя.

**Решение**: автоген имени при первом запуске + опция «Изменить имя» в настройках. Изменение раз в неделю (защита от свопа имени между поведенческими спайками).

- Шаблон автогена: `Normaldo-XXXX` (4 hex-символа от хэша device ID)
- Имя ограничено: 3–12 символов, латиница + кириллица + цифры
- Стоп-лист матерных слов (простой in-memory массив, расширяется)
- Дубликаты разрешены — отдельный `user_id` уникален

### Идентификатор и восстановление аккаунта

**MVP (Этап 2):** Firebase Anonymous Auth + recovery code.

Чистый anonymous auth теряет аккаунт при смене телефона или переустановке (UID хранится только в локальном Auth state). Чтобы дать игроку возможность защитить прогресс без OAuth и нативных плагинов, добавляем recovery code — простую запасную ссылку на аккаунт.

Поток:

1. **Первый запуск**:
   - Firebase Anonymous Auth выдаёт UID
   - Клиент генерирует код вида `NORM-A2F8-B71C-D9E0` (16 hex-символов в 4 группах)
   - Клиент отправляет `sha256(code)` на сервер → Cloud Function пишет `/recovery_lookup/{hash} → {user_id}` + `/users/{user_id}.recovery_code_hash`
   - Сам код **никогда не уходит на сервер в plain** — хранится только локально + показывается игроку
   - Показывается в Настройках, soft-prompt после первого крупного достижения («Запиши код, чтобы не потерять прогресс»)

2. **Смена устройства**:
   - На новом устройстве — кнопка «Восстановить аккаунт» на стартовом экране и в Настройках
   - Игрок вводит код → клиент шлёт `sha256(code)` в Cloud Function `restoreAccount`
   - CF находит UID по хэшу → возвращает Firebase Custom Token, подписанный для этого UID
   - Клиент логинится с custom token → Firebase Auth получает старый UID → весь прогресс восстановлен

3. **Если игрок потерял и устройство, и код** — прогресс утерян (приемлемая цена за простоту MVP).

**Что хранится локально (SaveData):**
```
recovery_code : String   # plaintext, для отображения в настройках
```

**Что хранится на сервере (Firestore):**
```
/users/{user_id}.recovery_code_hash : "sha256:..."
/recovery_lookup/{code_hash} → { user_id }
```

`/recovery_lookup` нужен для O(1) поиска UID по хэшу — Firestore не умеет эффективно искать по полю внутри коллекции без индекса, отдельная коллекция-маппинг проще и быстрее.

**После MVP (Этап 4+):** нативные платформенные auth — **Apple Game Center** на iOS и **Google Play Games** на Android. Они дают zero-effort cross-device:
- Игрок устанавливает игру на новый телефон под тем же Apple/Google аккаунтом
- ОС сама подсовывает стабильный платформенный ID
- Firebase `linkWithCredential` привязывает текущий anonymous UID к платформенному
- Прогресс автоматически на новом устройстве, без кодов

Требует нативных плагинов для Godot (`gd-game-center` / `godot-play-game-services`) + бюрократии (entitlements, App Store Review требует Sign in with Apple при наличии любых соц-логинов). Делаем когда аудитория оправдывает усилия.

Recovery code останется как запасной канал и после интеграции платформенного auth — для игроков, не залогиненных в Game Center / Play Games.

## Техническая реализация

**Бэкенд: Firebase Firestore + Cloud Functions** (согласовано).

Причины:
- Скорость запуска — за неделю можно собрать прод
- Scheduled Cloud Function для ресета недели и начисления призов
- Anonymous Auth закроет user_id из коробки
- Бесплатного tier хватит до десятков тысяч игроков
- Простая security rule «player может писать только в свой документ» закрывает большую часть тривиальных атак

### Схема данных (Firestore)

```
/users/{user_id}
   display_name: "Normaldo-7A2F"
   week_id: "2026-W24"            // текущая ISO неделя
   mode_best: {                   // рекорд недели по каждому режиму
     ep1: 186, ep2: 214, ep3: 0, endless: 247
   }
   pending_rewards: [
     { week: "2026-W23", metric: "endless", place: 12,
       dollars: 300, tokens: 1, claimed: false },
     { week: "2026-W23", metric: "ep1", place: 47,
       dollars: 300, tokens: 1, claimed: false }
   ]
   last_name_change: <timestamp>  // для лимита раз в неделю
   updated_at: <timestamp>

/leaderboards/{week_id}/{mode}/{user_id}      // mode: ep1 | ep2 | ep3 | endless
   user_id, display_name, avatar_skin, avatar_fat, score, updated_at

/meta
   current_week_id: "2026-W24"
   prize_distributed_for_week: "2026-W23"  // защита от дабл-распределения

/history/{week_id}
   distributed_at: <timestamp>
   snapshots/{mode}: { rows: [...] }   // снапшот топ-100 на каждый режим
```

Лидерборды режутся по неделе — после ресета старая ветка остаётся в `/history`, клиенту видна только текущая.

### Поток данных

```
[Забег кончился — смертью или победой над боссом]
    │
    └─→ HUD считает total_pizzas и знает СВОЙ РЕЖИМ (`_run_episode`)
        │
        └─→ submitScore { mode, score, run_seconds, avatar_skin, avatar_fat }
              │
              └─→ Cloud Function:
                  ├─→ mode ∈ { ep1, ep2, ep3, endless }, иначе отказ
                  ├─→ sanity check: score ≤ MAX(run_seconds) + buffer
                  ├─→ if score > mode_best[mode] → пишем строку таблицы режима
                  └─→ возврат { mode, best, rank, mode_best, week_id }
        │
        └─→ обновляется строка ранга на экране смерти

[Игрок открыл полный экран]
    │
    └─→ getLeaderboard { metric: <ep1|ep2|ep3|endless>, limit: 100 }
          │
          └─→ Cloud Function отдаёт топ-100 + total_players + reset_at

[Тап «Моя позиция» когда игрок ниже 100]
    │
    └─→ HTTPRequest GET /leaderboard/window?metric=best&user_id=X&radius=5
          │
          └─→ Cloud Function отдаёт окно ±5 строк вокруг user_id
```

### Scheduled Cloud Function — еженедельный ресет

```
cron: 0 0 * * 1   (понедельник 00:00 UTC)

действия:
  1. Прочитать /meta.current_week_id (предыдущая неделя)
  2. Для обеих метрик (best, total):
       - Прочитать всех ранжированных
       - Для каждого user определить place
       - Начислить prize по таблице → добавить в pending_rewards
  3. Сохранить топ-100 каждой метрики в /history/{week_id}
  4. /meta.prize_distributed_for_week = старая неделя
  5. /meta.current_week_id = новая неделя
```

Cloud Function запускается раз в неделю → дёшево.

### Защита от шулерства

На первом этапе — **минимально достаточно**:

1. **Sanity-bound на best**: формула от времени забега — `max_pizzas_per_sec * survived_seconds + buffer`. Если игрок присылает рекорд 1000 за 30 секунд игры — отвергнуть.
2. **Sanity-bound на total**: за неделю не может быть больше чем `7d * 24h * MAX_RATE` — это космос, отвергаем выше потолка.
3. **Throttle**: не более 1 submit_score в 30 секунд с одного user_id (защита от спама бота).
4. **Server-side timer**: длина забега считается клиентом и отправляется вместе с очками; сервер проверяет соотношение.

На втором этапе:
- **App Check** (Firebase) — подтверждает, что запрос идёт из настоящего бинаря приложения
- **Server-side verification**: вместо «сообщи свой score» отправлять «хэш забега» + лог ключевых событий, сервер проверяет соответствие

На первом этапе шулерство — небольшая проблема (игра ещё не известна). Делать сразу всё не нужно.

### Оффлайн / ошибки сети

- **Submit_score** не дошёл → положить в локальную очередь `pending_submits`, ретраить при следующем входе. Локально `SaveData.mode_best` уже обновлён, UX выглядит ок.
- **Получение лидерборда** не удалось → показать локальный кэш + бэйдж «офлайн, данные могут быть устаревшими». На экране смерти места показываются как `—`.
- **Pending_rewards** считывается при каждом успешном sync → не зависят от прохождения экрана смерти.

### Что хранится локально (SaveData)

Добавится:

```gdscript
var display_name        : String     = ""    # автоген или выбранный
var user_id_hashed      : String     = ""    # хэш device ID + salt
var mode_best           : Dictionary = {}    # рекорд недели по каждому режиму
var episodes_done       : int        = 0     # сколько эпизодов пройдено (замок вкладок)
var current_week_id     : String     = ""    # для детекции локального ресета
var pending_submits     : Array      = []    # очередь оффлайн submit_score
var cached_leaderboard  : Dictionary = {}    # последний загруженный топ
var cached_at           : float      = 0.0   # timestamp кэша
var last_name_change_ts : float      = 0.0   # для лимита переименования
var pending_rewards     : Array      = []    # призы, ждущие модалки
```

При смене недели (`current_week_id != server.current_week_id`) — локальный `mode_best` обнуляется. `episodes_done` к неделе не привязан: это прогресс кампании, а не результат недели.

## Этапы реализации

После согласования концепции — раскладываем на 3 задачи в Канбан.

### Этап 1 — UI на mock-данных
- Полный экран лидерборда работает на статичных данных в коде
- Обе вкладки (Рекорд / Объём), переключение
- Кнопка «Моя позиция» с фейковым окном
- Строка ранга на экране смерти (две метрики)

## Сервер надо ДЕПЛОИТЬ вместе с клиентом

Разбиение таблицы по режимам поменяло **обе** стороны: клиент стал слать `ep1`,
`ep2`, `ep3`, `endless` вместо прежних `best` и `total`, и функции в
`dev/firebase/functions/src/index.ts` научились их принимать. Но функции живут не
в сборке игры, а в облаке, и обновляются отдельно.

Пока сервер оставался старым, игрок видел:

```
400: { "error": { "message": "metric must be 'best' or 'total'",
                  "status": "INVALID_ARGUMENT" } }
```

Причём молча ломалась не только таблица: `submitScore` шлёт тот же `mode`, то
есть **результаты забегов тоже не доходили** — при живой сети и пройденной
авторизации. Снаружи это выглядело как «сервер молчит», а не как «мы забыли
выкатить».

Деплой:

```
cd dev/firebase/functions && npm ci && npx tsc --noEmit
cd .. && firebase deploy --only functions
```

**Правило: правка `index.ts` не считается сделанной, пока функции не
развёрнуты.** Клиент и сервер здесь — одна пара, и выкатывать их порознь можно
только в одну сторону: сперва сервер (он принимает и старое, и новое), потом
клиент.
