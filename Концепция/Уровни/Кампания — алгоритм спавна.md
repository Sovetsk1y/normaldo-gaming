# Кампания — алгоритм спавна

Полное техническое описание того, как спавнер работает в режиме кампании. Источник правды — `spawner.gd`.

---

## Структура кампании (7 минут)

6 фаз, 420 секунд суммарно. После последней — сигнал `boss_time`.

| Фаза | Длина | Скорость | Режим |
|------|-------|----------|-------|
| 0 | 60 с | 220 px/s | обычный |
| 1 | 80 с | 242 px/s | обычный |
| 2 | 90 с | 264 px/s | обычный |
| 3 | 90 с | 297 px/s | обычный |
| 4 | 80 с | 330 px/s | обычный |
| 5 | 20 с | 330 px/s | **pre-boss** (no_pizza) |
| **Итого** | **420 с** | | → `boss_time` |

На переходе между фазами спавнер делает паузу **0.8 с** перед первым паттерном новой фазы.

---

## Жёсткое intro (первые 3 паттерна)

Первые **3 паттерна** любого забега кампании всегда одинаковые: `_t1_center_line` — пицца на центральной дорожке (д3), бананы по бокам (д2, д4). Это онбординг под механику инерции — игрок сразу читает простейший сэндвич.

```
_campaign_intro_left = 3  (на старте)

каждый паттерн:
   если intro_left > 0:
       intro_left -= 1
       _t1_center_line()    (бананы, не баки)
   иначе:
       обычный _campaign_pick_pat_tier() → _dispatch_pat()
```

После intro `_t1_pattern_count` остаётся 0, поэтому `_t1_trash` ещё долго `false` — банановая прогрессия начинается с обычного T1 после 4-го паттерна.

В **бесконечном режиме intro не применяется** — там сразу случайный T1 по весам фазы.

---

## Главный цикл (каждый кадр)

```
_phase_elapsed += delta

если _pattern_running == false
   и _frozen == false
   и _spawn_timer <= 0:
      _pattern_running = true
      запустить _run_campaign_pattern() [async]

если _phase_elapsed >= длина фазы:
      _phase += 1
      _phase_elapsed = 0
      если _phase >= 6: emit boss_time; стоп
      иначе: _spawn_timer = 0.8
```

---

## Выбор тира паттерна

Функция `_campaign_pick_pat_tier()` делает **взвешенный случайный выбор** из 4 категорий: T1, T2, T3, T4/T5. Вероятности нарастают к тяжёлым тирам с каждой фазой.

| Фаза | T1 | T2 | T3 | T4/T5 |
|------|----|----|----|-------|
| 0 | 70 % | 30 % | 0 % | 0 % |
| 1 | 20 % | 50 % | 30 % | 0 % |
| 2 | 0 % | 20 % | 40 % | 40 % |
| 3 | 0 % | 10 % | 30 % | 60 % |
| 4 | 0 % | 0 % | 20 % | 80 % |

Тир 3 и тир 4 (`T4/T5`) идут через один диспетчер `_dispatch_t45` — он сам чередует перчатки и молотовы батчами.

---

## Цикл одного паттерна

```
1. _campaign_pick_pat_tier()  →  выбрать тир (0–3)
2. _dispatch_pat(tier, ...)   →  отыграть паттерн [await]
3. await 0.25 с
4. бросить кубик: randf() < BONUS_CHANCES[phase_pt]
      если да → _spawn_bonus_item(...)
5. await POST_PAT_GAPS[phase_pt]
6. _pattern_running = false  →  цикл подхватит следующий паттерн
```

### Паузы и бонус-шансы по тирам фазы

| Тир фазы | Пауза после паттерна | Шанс бонуса |
|----------|---------------------|-------------|
| T1 (ф. 0) | 1.50 с | 10 % |
| T2 (ф. 1) | 0.65 с | 12 % |
| T3 (ф. 2) | 0.80 с | 14 % |
| T4 (ф. 3) | 0.70 с | 16 % |
| T5 (ф. 4) | 0.60 с | 18 % |

> Пауза и шанс берутся из индекса `phase_pt = mini(_phase, 4)` — то есть привязаны к номеру фазы, а не к случайно выбранному тиру паттерна.

### Бонусные предметы

При срабатывании бонуса на случайную дорожку вылетает:

| Предмет | Вес |
|---------|-----|
| Магнит | 30 % |
| Мешок с деньгами | 25 % |
| Бумбокс | 25 % |
| Пицца-пак | 20 % |

## Батчи T4/T5

`_dispatch_t45` чередует волны перчаток (T4) и молотовов (T5) **батчами**:

```
Батч-последовательность: [3, 3, 5, 5, 8, 8]
Чётный индекс батча → T4 (перчатки)
Нечётный индекс батча → T5 (молотовы)
После батча [8, 8] — цикл зацикливается на [8, 8]
```

Пример:
```
3× T4 → 3× T5 → 5× T4 → 5× T5 → 8× T4 → 8× T5 → 8× T4 → ...
```

## T1 — особые правила

### Замедлители: бананы → мусорные баки

Счётчик `_t1_pattern_count` инкрементируется при каждом вызове `_pat_t1`.

```
_t1_trash = (_t1_pattern_count > 5)

_t1_pattern_count 1–5  →  _t1_trash = false  →  бананы (замедление, 0 урона)
_t1_pattern_count 6+   →  _t1_trash = true   →  мусорные баки (урон = 1)
```

### Пицца гарантирована

Во всех 6 вариантах T1-паттернов пицца спавнится **всегда** — никакого `randf() < 0.5`.

### Пицца между тоннелями

В многосекционных паттернах (Вар.3–6) пауза между разделами разбита на два отрезка с пиццей посередине:

```
конец секции
    await gap × 1.2
    spawn pizza на д3 (центральная дорожка)
    await gap × 1.3
начало следующей секции
```

Итого пауза между секциями = `gap × 2.5` — то же время, что раньше, но теперь с пиццей в середине.

### Осцилляция позиций

После 30 секунд внутри фазы все предметы T1 начинают дрожать по вертикали:

```
oy = sin(phase_elapsed × 0.8) × 25 px   (если phase_elapsed > 30)
oy = 0                                   (первые 30 с)
```

## Варианты T1-паттернов (6 штук, равновероятны)

| # | Функция | Структура |
|---|---------|-----------|
| 0 | `_t1_double_line` | 5 столбцов: 🍕 д1 + 🍌/🗑️ д2 + · д3 + 🍌/🗑️ д4 + 🍕 д5 → бумбокс на д1 или д5 |
| 1 | `_t1_center_line` | 5 столбцов: · д1 + 🍌/🗑️ д2 + 🍕 д3 + 🍌/🗑️ д4 + · д5 |
| 2 | `_t1_two_sandwiches(down=true)` | сэндвич на д2 (5 стб) → 🍕 д3 → сэндвич на д4 (5 стб) |
| 3 | `_t1_two_sandwiches(down=false)` | сэндвич на д4 (5 стб) → 🍕 д3 → сэндвич на д2 (5 стб) |
| 4 | `_t1_cascade(down=true)` | чанк д2 (4 стб) → 🍕 д3 → чанк д3 (4 стб) → 🍕 д3 → чанк д4 (4 стб) |
| 5 | `_t1_cascade(down=false)` | чанк д4 (4 стб) → 🍕 д3 → чанк д3 (4 стб) → 🍕 д3 → чанк д2 (4 стб) |

Сэндвич = `🍌/🗑️ | 🍕 | 🍌/🗑️` на трёх соседних дорожках.

## Pre-boss фаза (Фаза 5)

20 секунд давления без пиццы перед боссом:

```
_campaign_pre_boss_pattern:
    выбрать тип: перчатки (50%) или молотовы (50%)
    выбрать safe_lane = rand(0..4)
    
    3 волны:
        запустить оружие на все 4 дорожки кроме safe_lane
        safe_lane = (safe_lane + 2) % 5
        await col_gap × 1.3  (между волнами 1→2 и 2→3)
```

Сдвиг safe_lane на +2 (а не +1) гарантирует, что безопасная дорожка перепрыгивает через одну — игрок не может просто «сползти» на соседнюю, нужно резкое движение с инерцией.

### Дождь ресурсов (поверх pre-boss)

Параллельно с волнами молотовов/перчаток на pre-boss-фазе работает **loot-rain** — периодические пачки пицц и долларов в стиле взрыва `money_bag`, но крупнее. Игрок видит как одна за другой влетают «вкусные» пачки, и тут же огневые зоны молотовов их сжигают (огонь и зона приземления молотова чистят группы `pizza`/`dollar`).

```
_start_pre_boss_resource_rain → _pre_boss_resource_loop:
    каждые 2.0 с пока phase == 5 и не _frozen:
        N = randi_range(12, 16) предметов
        Y-позиции — равномерно по высоте экрана с jitter ±35% от шага строк
        X-офсет — randf(40..220) для лестничной развёртки появления
        для каждого:
            20% → доллар (item_group="dollar", scale 0.36)
            80% → пицца  (is_eatable, scale 0.09)
```

Запуск — в `_process()` сразу после `phase_entered.emit()` для последней фазы, плюс дублируется в `dev_skip_to_next_phase()` чтобы дев-скип в pre-boss тоже сразу включал дождь. Цикл сам выходит при `_frozen=true` (смерть/reset) или когда `_phase` уходит за индекс pre-boss (босс/конец кампании).

Константы — `PRE_BOSS_BURST_INTERVAL`, `PRE_BOSS_BURST_COUNT_MIN/MAX`, `PRE_BOSS_DOLLAR_RATIO` в `spawner.gd`.
