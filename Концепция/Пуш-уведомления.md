# Пуш-уведомления

## Цели

1. **Retention** — возвращать игрока в первые 7 дней после установки, потом — раз в неделю.
2. **Утилизация механик** — напоминать о бесплатных ресурсах (логин-бонус, спин в автомате, награды за задания), которые иначе сгорят на ресете дня.
3. **Прогресс** — подсвечивать «вот-вот возьму уровень / награду / босса», когда игрок близок к чекпоинту.
4. **События** — точечно дёргать на закрытие еженедельной таблицы лидеров, разблокировку бесконечного и крупные контент-апдейты.

## Принципы

- **Голос совпадает с тоном меню/HUD** — короткие, чуть нахальные фразы, без морализаторства и без «не пропусти». Канализация, пицца, ниндзя, мастерство — это словарь.
- **Один пуш в сутки на категорию** (см. правила частоты ниже). Никаких «5 раз за вечер».
- **Локальный приоритет**. Большая часть — локальные нотификации, шедулящиеся при выходе из игры; remote-пуши только под события, которые невозможно знать на клиенте (лидерборд, кросс-игроки, ручные контент-анонсы).
- **Тихие часы** — 23:00–09:00 локального времени не дёргаем. Если триггер попадает в окно, переносим на 09:00 след. дня.
- **Подстановки** — `{nick}`, `{skin_name}`, `{streak}`, `{xp_left}`, `{place}`, `{prize}` и т.п. Если данных нет (нет ника / нет места) — используем безопасный fallback-вариант текста без подстановки.

## A. Re-engagement (вернуть забывшего игрока)

| ID | Триггер | Заголовок | Тело |
|---|---|---|---|
| A1 | Прошёл 1 день после последнего захода; шлём в 18:00 | Пицца стынет | Нормальдо смотрит на сковородку и грустит. {streak_safe_hint} |
| A2 | Прошло 3 дня | В канализации тихо… | Слишком тихо. Ниндзи это нравится. |
| A3 | Прошло 7 дней | {nick}, твой скин просит апа | До нового уровня {skin_name} оставался один забег. |
| A4 | Прошло 14 дней | Учитель закрыл книгу | Но не до конца. Заглянешь? |
| A5 | Прошло 30 дней | Вернись — и я ничего не скажу | На входе бонус «как давно не виделись». {comeback_gift} |

> `{streak_safe_hint}` — если активный streak ≥ 3: «Стрик {streak} дней — не теряй». Иначе — пусто.
> `{comeback_gift}` — описание подарка, реально кладётся в pending_rewards перед отправкой A5. Заполняем серверно или локальным «возвращенцу +N жетонов».

**Частота:** одно A-уведомление за серию отсутствия. После клика серия сбрасывается.

## Правила приоритетов и частоты

1. **Жёсткий потолок** — не больше **2 пушей в сутки на игрока** суммарно, даже если совпадает несколько триггеров.
2. **Очередь приоритетов** при коллизии в одной точке времени (сверху — выше):
   1. F (pending награды) — у игрока буквально на счету ждут жетоны
   2. E2 (бесконечный открыт) — one-shot важное событие
   3. G1/G2 (лидерборд закрывается / обгон)
   4. A-серия (re-engagement)
   5. B-серия (ежедневный цикл)
   6. C/D/E1/E3 (прогресс-нотификации)
   7. H (контент, ручные)
3. **Сброс серий**: любой запуск игры за день обнуляет план «retention»-цепочки (A-серия) и снимает с очереди уведомления, которые в этот день уже не имеют смысла (B1 если игрок зашёл утром, D1 если он уже скрутил спин, …).
4. **Тихие часы** — 23:00–09:00. Триггер, попавший в окно, **переносится на 09:00 следующего дня**, а не отменяется.

## Настройки игрока

Один экран в `СНАСТРОЙКИ → УВЕДОМЛЕНИЯ` с тогглами по категориям:

- **Возвращение** — A
- **Ежедневные напоминания** — B
- **Прогресс скина** — C
- **Бесплатные награды** (слот D + награды F) — объединённо
- **Сюжет и босс** — E
- **Лидерборд** — G
- **События и контент** — H

По умолчанию все включены. Отдельно — мастер-переключатель «все уведомления».

Также храним:

- `notif_quiet_hours_start` / `..._end` (по умолчанию 23 / 9) — игрок может растянуть/сузить тишину.
- `notif_last_sent_at` — для соблюдения daily-cap при следующей перепланировке.

## Аналитика

Отправляем GA4-события (через существующий `analytics.gd`):

- `notif_scheduled` — `{ id, category, fire_at, scheduled_at }`
- `notif_fired` — `{ id, category }` (если ОС подтвердит; iOS Notification Service Extension)
- `notif_opened` — `{ id, category, latency_secs }`
- `notif_dismissed` — приближённо: разница между `notif_fired` и активным сеансом > 24 ч
- `notif_permission` — `{ status: "granted"|"denied"|"provisional" }` при первом запросе

Имена событий уже соблюдают правило префикса (см. `feedback_ga4_reserved_names`).

## Технические замечания (передача в следующий шаг)

- Большая часть уведомлений — **локальные на устройстве** (расписание задаётся на клиенте при выходе из игры или при ключевых событиях).
- Remote-пуши (G2, H, F с серверной стороны) —
- через **Firebase Cloud Messaging**, поверх той же Firebase-инфры, что используется для лидерборда.
- Permission prompt на iOS — показываем **после первой смерти**, а не на старте: к этому моменту игрок понимает ценность.
- Android 13+ — `POST_NOTIFICATIONS` runtime-разрешение, такая же логика.

### Реализация нативных бэкендов

Единый фасад `Notifications` (GDScript autoload) с одинаковым контрактом
(`schedule/cancel/cancel_category/cancel_all`, `has_permission/request_permission`,
`drain_pending_taps` + сигналы `tap_buffered`/`permission_changed`); планировщик
`NotifPlanner` платформо-независим. За фасадом — два нативных синглтона:

- **iOS** — `NotifPluginIOS`, GDExtension (ObjC++ `UserNotifications`,
  calendar-триггер с секундной точностью). ОС сама доставляет пуш в назначенное
  время — код приложения в этот момент не нужен.
- **Android** — `NotifPluginAndroid`, **Godot Android-плагин (Kotlin)**, НЕ
  GDExtension. Причина: доставка в killed-состоянии требует `AlarmManager` +
  manifest-`BroadcastReceiver` (ОС создаёт его по имени класса из APK) — `.so`
  GDExtension живёт только внутри процесса Godot и этим receiver'ом быть не может.
  Точные алармы (`setExactAndAllowWhileIdle`, `SCHEDULE_EXACT_ALARM`) с откатом на
  неточные, когда ОС не даёт разрешение; пере-арминг будущих пушей на
  `BOOT_COMPLETED`; состояние id↔payload в `SharedPreferences`.

### Remote-пуши (серверные категории)

Поверх того же фасада. Транспорт раздельный, за одним серверным хелпером:
- **Android — FCM.** `FirebaseMessagingService` в плагине; сервер шлёт **data-only**
  сообщения (`onMessageReceived` строит уведомление через `NotifScheduler`,
  сохраняя deep-link). FirebaseApp инициализируется программно (без
  google-services.json в сборке).
- **iOS — сырой APNs.** GDExtension регистрируется на remote-notifications и
  ловит APNs-токен через swizzling app-делегата (`get_push_token` + сигнал
  `push_token`). Alert-пуши показывает ОС, тап идёт через тот же
  `UNUserNotificationCenterDelegate`. Сервер шлёт на iOS напрямую через APNs
  HTTP/2 (.p8-ключ).
- **Токен** регистрируется на сервере через `LeaderboardClient.register_push_token`
  (тот же auth, `users/{uid}`), дедуп по `SaveData.registered_push_token`.
- **Сервер** (`dev/firebase/functions`): `registerPushToken`, хелпер
  `sendPushToUser` (FCM/APNs по платформе), `sendTestPush` (dev),
  `sendCampaign` (admin, H1/H2). **G2** — триггер `onLeaderboardWrite`
  (обнаружение обгона: счёт между старым и новым, только активные ≤10 ч,
  троттлинг 6 ч, топ-100); **G3** — пуш призов в `weeklyReset`. Оба тапа ведут
  на `deep_link: "leaderboard"`. F1 (напоминание о незабранных наградах) —
  локально через `NotifPlanner._plan_f`.

Пререквизиты: Firebase App ID + Sender ID (Android), APNs .p8 + Key/Team ID (iOS).
