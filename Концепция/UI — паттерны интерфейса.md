# UI — паттерны интерфейса

Общий словарь для всех экранов. Заведён потому, что интерфейс собирается кодом,
и каждая новая панель до сих пор рисовалась заново: скругления, отступы и
тайминги нажатия у экрана скинов, наград и заданий разъезжались, хотя выглядеть
должны одинаково.

Правило простое: **делаешь новый экран — сначала ищи кирпич здесь.** Нет
подходящего — добавь его сюда вместе с кодом.

## Кирпичи

| Кирпич | Где код | Что это |
|---|---|---|
| Скруглённая панель | **`UiKit.rounded()` / `UiKit.panel()`** (`scripts/ui_kit.gd`) | Подложка с радиусом и рамкой. 12 — карточка, 10 — пилюля, 8 — кнопка и чип, 6 — полоса |
| Положить и задать размер | **`UiKit.place()`** (`scripts/ui_kit.gd`) | `add_child`, и ТОЛЬКО потом `size`. См. правило ниже |
| Кнопка действия | `quests_screen._claim_button()` | Панель + подпись + невидимый `Button` сверху, с усадкой при нажатии |
| Усадка при нажатии | **`UiKit.press_anim()`** (`scripts/ui_kit.gd`) | ×0.90 за 0.07 c, обратно за столько же. Один тайминг на всю игру — и одно место, где учтено, что кнопка переживает свой экран |
| Чип | `quests_screen._build_reset_chip()`, шапка лидеров | Маленькая скруглённая плашка с текстом: таймер, счётчик, статус |
| Полоса прогресса | `quests_screen._build_progress_bar()` | Тёмный жёлоб + заливка цветом сущности + числа ПОВЕРХ полосы |
| Иконка + число | `_make_icon()` + подпись справа | Валюта всегда спрайтом, никогда текстом «100 $» |
| Кружок способности | `hud._ability_badge()` | Иконка в цветном кольце, с замком если закрыто |
| Медальон с номером | `quests_screen._build_tier_badge()`, подиум лидеров | Кружок с цифрой + слово рядом. Кодирует уровень дважды |
| Вкладки-пилюли | `leaderboard_screen._set_tab_style()` | Активная — залитая пилюля с тёмным текстом, неактивная — контурная с тусклым |
| Подиум | `leaderboard_screen._build_podium()` | Первая тройка карточками: центральная шире и выше боковых |
| Закреплённая своя строка | `leaderboard_screen._build_my_strip()` | Полоса внизу экрана: «ты такой-то», тап — прыжок к себе в списке |
| Чип на портрете | `hud._build_skin_grid_cell()` | Маленькая плашка поверх аватара: уровень скина. Не тратит отдельную строку |
| Карточка коллекции | `hud._build_skin_grid_cell()` | Редкость словом, портрет, имя, полоса и кнопка состояния — в 150×110 |
| Колонка карточки | `hud._detail_panel()` | Скруглённая панель с заголовком; не влезло — скролл внутри, а не обрезка |
| Разворот | `achievements_screen._layout()` | Две страницы: слева оглавление с прогрессом по разделам, справа содержимое выбранного. Так длинный список перестаёт быть лентой |
| Строка-раздел | `achievements_screen._build_chapter_row()` | Медальон с номером, название, мини-полоса и счётчик. Выбранная — светлее и в рамке акцентом |
| Метка «есть что забрать» | `achievements_screen._build_chapter_row()` | Золотая точка на свёрнутом разделе: единственный способ увидеть готовую награду, не открывая его |
| Арт как корпус | `slots_screen._build_machine()` | Кабинеты — пиксель-арт, обрезанный по `MACH_CUT`; окно барабана берётся из арта, а не задаётся числом. Три штуки вплотную на общей подложке = один автомат |
| Строка результата | `slots_screen._note_result()` | Что выпало, остаётся написанным после закрытия окна выигрыша |
| Лента последних | `slots_screen._refresh_history()` | Три последних исхода значками и суммой. Память сессии, в сейв не пишется |
| Строка рекорда | `hud._build_go_left()` | «Не хватило 69» / «НОВЫЙ РЕКОРД» / «первый забег». Сравнение — со снимком рекорда ДО забега |
| Разрушительное действие | `pause_screen._build_run_panel()` | Выход вдвое уже продолжения и контурный. Размер и заливка, а не только красный цвет |
| Экран поверх паузы | `pause_screen`, `settings_screen` | `PROCESS_MODE_ALWAYS` + z_index выше паузы. Иначе экран замирает вместе с игрой, и кнопки не нажимаются |
| Переключатель | `settings_screen._toggle_row()` | Пилюля с кружком и словом `ВКЛ`/`ВЫКЛ`. Заливка, положение кружка и слово — три признака на одно состояние |
| Метка на объекте | `scripts/resist_marks.gd` | Статус рисуется НА игровом объекте, а не в углу экрана: в бою взгляд живёт на объектах, а не на HUD |
| Перелёт награды | `quests_screen._fly_icons_to()`, `minigame_payout._fly_to_hud()` | Иконки летят в счётчик HUD, счётчик щёлкает по прилёту |
| Въезд экрана | `quests_screen` `SLIDE_TIME`/`SLIDE_TRANS` | «Проезд камеры»: экран приезжает снизу, меню уезжает вверх, одним таймингом |
| Переезд свойства | **`UiKit.slide_to()`** (`scripts/ui_kit.gd`) | «Доехать отсюда туда» одним твином. Вне дерева значение ставится напрямую — доедет в любом случае |
| Кнопка главного экрана | **`hud._build_menu_icon_btn()`** | Круглая шайба со свечением + подпись под ней. Размер и место задаются в координатах полотна 430×192, а не в пикселях экрана |

## Правила

**Состояние никогда не передаётся одним лишь цветом.** У каждого состояния есть
слово, а часто и значок: `ЗАБРАТЬ` / `ИДЁТ` / `✓ ЗАБРАНО`, уровень сложности —
цифра в медальоне плюс `ЛЁГКОЕ`/`СРЕДНЕЕ`/`ТЯЖЁЛОЕ`, закрытый резист — замок
поверх кружка. Цвет только усиливает то, что уже сказано словом.

**Контраст текста на подложке не ниже 4.5:1.** Заголовки — почти белые,
пояснения не тусклее 0.80 белого. Подпись цветом сущности (золото награды,
зелень выполненного) допустима только на крупном кегле.

**Валюта — спрайтом.** `TEX_DOLLAR`, `TEX_TOKEN`, `TEX_MONEYBAG`. Текст «+100 $»
внутри игрового экрана читается как заглушка.

**Ничего важного за скроллом.** Экраны альбомные (960×430) — если контент не
влезает, сначала попробуй разложить в ряд, и только потом заводи скролл.

**Размер задаётся ПОСЛЕ `add_child`.** Пока `Control` не в дереве, он не видит
темы сцены и зажимает `size` по минимальному размеру темы по умолчанию — для
подписи это 48 px по высоте. Выставленные заранее 24 молча становятся 48, и
обратно Godot размер уже не ужимает. Там, где строки стоят просторно, этого не
видно, а в плотной таблице последняя строка вылезает за панель. Для этого есть
`UiKit.place(parent, ctrl, pos, size)`.

**Кнопка переживает свой экран.** Сигналы у Godot идут в порядке `pressed` →
`button_up`, а следом вьюпорт шлёт `mouse_exited`, когда вынимает кнопку из
дерева. То есть анимация нажатия доигрывает УЖЕ ПОСЛЕ того, как обработчик увёл
игрока с экрана. Выход из забега при этом зовёт `reload_current_scene()`, а тот
вынимает сцену из дерева **сразу**, удаляя только на следующем кадре: в этом
окне узел ещё `is_instance_valid()`, но `create_tween()` возвращает null. Отсюда
«Cannot call method 'set_pause_mode' on a null value» по кнопке выхода. Проверять
надо не валидность, а `is_inside_tree()`.

Само по себе это мелочь на три строки. Важно другое: защита от этого была
написана один раз — в `hud._menu_btn_press_anim()`, — а усадка к тому моменту
жила **семью копиями**, по копии на экран. Шесть остальных её не получили, и
баг ждал ровно того экрана, который позовёт перезагрузку сцены. Поэтому кирпич
теперь один, `UiKit.press_anim()`, а экраны только делегируют в него.

**Отцепленный узел приходит не только от кнопки.** Та же беда вылезла ещё
дважды, и оба раза с другой стороны. У `UiKit.pulse()` — потому что узел ЕЩЁ не
в дереве: карточку собирают отдельной функцией и добавляют потом, `create_tween()`
молча возвращает null, и пульсация не заводится — экран выглядит собранным
правильно, просто ничего не движется. У въезда интерфейса забега — потому что
обработчик дёргает **чужой** узел: крокодил на своём `tree_exited` возвращает
интерфейс на место, а «ЕЩЁ РАЗ» на экране смерти вынимает из дерева обоих. Босс
уходит первым, зовёт обработчик у уже отцепленного HUD — «Cannot call method
'tween_property' on a null value».

Отсюда правило шире, чем «проверь `is_inside_tree()`»: **любая анимация, которую
может позвать не свой узел, обязана уметь работать без твина**. И не «выйти, если
не в дереве», а ДОВЕЗТИ значение напрямую — иначе интерфейс останется стоять за
краем экрана. Для этого есть `UiKit.slide_to()`.

Проверять это на Godot 4.3 бессмысленно: null там не возвращается, проект же
собирается 4.2. Поэтому `dev/smoke_death.gd` проверяет не падение, а свойство,
из-за которого падать нечему: вне дерева `slide_to()` и оба слайда интерфейса
довозят значение сразу.

**Подэкран открывается ПОВЕРХ, а не вместо.** Модалка, которая закрывает
родителя и открывает следующую, ломает возврат: закрыл вторую — оказался не
там, откуда пришёл. Если разделов больше двух, это не стопка модалок, а
разворот с оглавлением.

**В бою информация идёт к взгляду, а не наоборот.** Пока экран статичный, HUD
в углу читается. В забеге глаза прикованы к герою и к тому, что в него летит —
кружок в углу можно увеличить втрое, и его всё равно «не будет видно». Такой
статус рисуется прямо на объекте, о котором он говорит.

**Неподвижный индикатор — это шум.** Кружок, который весь забег один и тот же,
не сообщает ничего, зато глаз перестаёт замечать вместе с ним и соседние.
Постоянные свойства — на карточку до забега, в бою показываем то, что меняется.

**Движется ровно один элемент.** Пульсирует то единственное, к чему игрок должен
подойти: готовая к получению карточка, доступный уровень. Два пульсирующих
элемента на экране гасят друг друга.

## Иконки главного экрана

Кнопки меню — **самостоятельные спрайты**: круглая шайба и нарисованное вокруг неё
свечение. `hud._build_menu_icon_btn()` кладёт такую шайбу и подписывает её снизу.
Геометрия описана в единицах авторского замера — кадр 55×55, круг ~35, по 10 на
свечение, — а печатается в четырёх пикселях на единицу (см. «Плотность» ниже).

Прошлым кнопкам под это было нужно три вещи, которых больше нет:

* **Атлас.** Каждая иконка лежала ВНУТРИ полотна 430×192 вместе со всем меню, и
  её вырезали по вручную замеренному bbox — на каждую кнопку своя строка вида
  `Rect2(347, 40, 34, 28)`.
* **Отдельная подложка свечения.** Halo пекли скриптом (`dev/tools/bake_menu_glow.py`)
  в парный `*_glow.png` и клали под иконку с запасом полей.
* **Зелёная плашка под подпись.** Она была частью рисунка, и подпись ложилась на
  неё поверх — отсюда параметры `plate_y_in_btn` и `plate_h` у каждой кнопки.

Теперь свечение внутри спрайта, плашки нет, и подпись держится своей обводкой —
той же, что у остальных надписей меню.

**Подпись садится на низ ШАЙБЫ, а не кадра.** Круг занимает 0.64 кадра — остальное
нарисованное свечение, оно прозрачное. Подпись, посаженная по кадру, уезжала на
восемнадцать процентов высоты вниз, то есть на пустоту, и читалась как подпись к
чему-то ниже. По той же причине метка «есть что забрать» вешается на верхний
правый угол круга: по углу кадра она отъезжала в прозрачное поле и у нижних кнопок
читалась как метка соседней сверху.

**Шаг в правом столбце стал ровным.** У старых кнопок он гулял (27 / 45 / 34
канвас-px): плашки с подписями были разной высоты, и ряд выравнивали по ним.
Плашек больше нет, кнопки одинаковые — и шаг обязан быть одинаковым тоже.

Размеры и позиции по-прежнему задаются **в координатах полотна 430×192**, а не в
пикселях экрана: так меню не разъезжается между устройствами.

Индикатор «есть что забрать» остаётся программным на всех кнопках. У первой
версии иконки «ЗАДАНИЯ» красная точка была нарисована прямо в спрайте, и рядом с
живым индикатором получалось две точки: нарисованная горела всегда, живая — по
делу. Иконку перерисовали без точки — и индикатор снова означает то, что должен.

### Шайба собирается скриптом, а не рисуется

Пять иконок из шести собраны из ГОЛЫХ рисунков (`dev/art/menu_icons/`) скриптом
`dev/tools/bake_menu_icon.py`, и только слоты пришли готовой картинкой.

Собираются они потому, что шайба у шести кнопок обязана быть ОДНА И ТА ЖЕ. Ряд из
четырёх кругов не прощает ни съехавшего на пиксель кольца, ни чуть другого
ореола: это читается не как разнообразие, а как брак. Поэтому геометрия шайбы не
придумана, а СНЯТА ЗАМЕРОМ с готовой иконки слотов — круг d=35 в кадре 55×55,
кольцо #5704EF в два пикселя, заливка чёрным на 75 %, ореол со спадом альфы по
замеренной таблице, — и одна и та же функция кладёт её под каждый рисунок.

**Тёмному рисунку — белая обводка, остальным нет.** Шайба почти чёрная, и чёрные
гаечные ключи «НАСТРОЕК» или тёмно-синяя шапочка «ЗАДАНИЙ» на ней читались как
дырка в круге. Обводка в один пиксель возвращает силуэт. Жёлтой короне и зелёной
книге она не нужна и вредна — съела бы их собственную. Так же решено и в наборе
автора: белый контур там есть ровно у одной иконки, чёрной.

**Имя файла — это назначение кнопки, а не что нарисовано.** `skins.png` сегодня
череп, а завтра что угодно; менять из-за этого константу в `hud.gd` не придётся.

### Плотность: почему файлы 220×220, а не 55×55

Экранный размер иконки задан **в координатах полотна 430×192**
(`MENU_ICON_CANVAS = 34`) и от размера файла не зависит вовсе. В окне 960×430
кадр иконки выходит 76 px, а на телефоне 2400×1080 — около **190**: режим
растяжения `canvas_items` рисует всё в пикселях устройства.

Пока файлы были 55×55, это означало раздув **×3.45**. С фильтром `NEAREST`
каждый пиксель рисунка становился квадратом в 3–4 пикселя, причём неровным —
3.45 не целое число, — и круглая шайба шла ступеньками разной высоты. Именно это
и читалось как «иконки заквадратились», и хуже стало ровно тогда, когда кадр
подняли с 28 до 34 канвас-px: рисунок остался тот же, увеличение выросло.

Оригиналы автора при этом **500×500** — разрешение не отсутствовало, его
выбрасывали на выпечке. Скрипт печёт набор с плотностью `K = 4`, то есть в файл
220×220: те же 190 экранных пикселей берутся теперь из 220 — лёгкое уменьшение
вместо раздува втрое. **Экранный размер не изменился ни на пиксель**, изменилась
только плотность.

Парная к этому правка — **фильтр `LINEAR` вместо `NEAREST`**. Пиксель файла
здесь не равен пикселю экрана ни при какой плотности: размер задан в координатах
полотна, экран у каждого свой, масштаб дробный всегда. Nearest на дробном
масштабе рвал бы иконку и на уменьшении тоже. Тем же одним словом чинится чип
режима («ЭПИЗОД 1»): у него собственное свечение уже рисовалось линейно, а сама
картинка — nearest, и гладкий ореол окружал квадратную кнопку.

Два исключения, у которых нет оригинала крупнее: **СЛОТЫ** (готовая картинка
автора, 55×55) и картинка чипа режима (64×64). Квадратов у них больше нет —
линейный фильтр их убрал, — но и резкости взяться неоткуда: они мягче остальных.
Придёт от автора исходник — пересобираются вместе с набором.

Следит за этим `dev/smoke_menu_icons.gd`: он меряет у всех шести файлов кадр,
ПЛОТНОСТЬ, цвет кольца и спад ореола — по МЕДИАНЕ вдоль кольца радиуса, а не в
точке. Плотность проверяется отдельной строкой, потому что вернуть набор в 55 px
можно одним неверным `K` в скрипте, а на глаз в файлах разницы не видно —
