# Эпизод 1 — прогрессия предметов (редизайн)

> **Статус: РЕАЛИЗОВАНО (2026-07-01).** ТЗ на переработку спавна первого эпизода
> (7 минут до босса «Нога ниндзя»).
> Реализация в `scripts/spawner.gd`: кампания больше НЕ гоняет
> `_campaign_pick_pat_tier`/`_dispatch_pat` — вместо неё **директор**
> `_run_campaign_pattern` (одна «единица» за вызов: RANDOM-burst или SET-PIECE),
> конфиг `CAMPAIGN_DIRECTOR` по фазам. Эндлесс не тронут.
> Мини-игры: **лёгкий вариант** — гейт по `first_delay` (ЖИРОБОСС 55 / Пицца-пати
> 105 / Слоты 235 c) + Слоты `_episode_done` (1× за кампанию) + существующий
> мьютекс `is_busy()`. Полноценный `EP1_EVENT_WINDOWS`-scheduler и правило «не два
> подряд» пока НЕ делали (можно добавить позже).

## Зачем переделываем

Сейчас весь спавн кампании — это **только жёстко заскриптованные паттерны**
(T1–T5), выбираемые по весам фазы. Плюсы: читаемость, структура. Минус: **всё
предсказуемо и однообразно** — нет «живого» случайного потока, экран состоит из
одинаковых заготовок.

**Цель редизайна — гибрид:**

1. **Вернуть случайную генерацию** — базовый поток предметов сыпется по взвешенному
   рандому (как в старом спавнере), чтобы забег ощущался живым и разным.
2. **Оставить возможность подавать конкретные сценарии** — «сет-writing»
   (заготовки): *шахматы с камнями, столбы из змей, волны перчаток, волны
   молотовов* и др. Это управляемые пики/биты сложности.
3. **Чёткая 7-минутная кривая** — понятная прогрессия: что, когда и как часто.

Идея простыми словами: **случайный фон + режиссёр, который время от времени
вставляет постановочную сцену**.

---

## Модель: «Директор»

Вместо `_run_campaign_pattern` (который каждый раз запускает один паттерн) — цикл
**директора**, который чередует два типа окон:

- **RANDOM-окно** (`_random_window`): несколько секунд сыплется **случайный поток**
  из пула предметов текущего бэнда (с гарантией безопасной дорожки).
- **SET-PIECE-окно** (`_set_piece_window`): директор ставит на паузу рандом и
  запускает **одну заготовку** из пула бэнда, затем даёт **вздох** (breather).

```
[рандом 6с] → [СЕТ-ПИС: столбы змей] → вздох → [рандом 5с] → [СЕТ-ПИС: шахматы] → …
```

- **Рано** (0–2 мин): длинные RANDOM-окна, редкие и простые сет-writing.
- **Поздно** (5–7 мин): короткие RANDOM-окна (плотнее), частые и тяжёлые
  сет-writing, иногда **комбо** (сет-пис + рандом-оверлей).

Каденс сет-writing и плотность рандома управляются **бэндом** (см. таблицу ниже).

## Библиотека предметов (случайный пул)

Базовый рандом сыплет **по одному предмету** за спавн (лейн + тип по весам). Пул
делится на группы; **летальные телеграф-угрозы (перчатка/молотов/бомба) в рандом НЕ
попадают** — они приходят только как читаемые сет-writing (иначе нечестно).

| Группа | Предметы | Роль |
|---|---|---|
| **Ресурсы** | пицца, доллар, мешок долларов (редко), магнит (редко) | набор жира + валюта + бонусы |
| **Замедление** | банан, пиво | мягкая угроза (slow), не убивает |
| **Простые препятствия (1 урон)** | бочка, камень, бомж, собака, змея | базовая угроза, читается легко |
| **Только в сет-writing** | перчатка, молотов, бомба, огонь | летальные постановки |

**Смерть предметов:** уничтоженный предмет **не исчезает мгновенно**, а
**падает с вращением** (как в мутагене — `knock_down`), а бомжи и собаки при этом
**кричат предсмертным звуком** (`homeless_die*`/`dog_die*`). В `normaldo.gd` все
пути уничтожения (резист, Рыгалити/спеллы, обычный удар, маска Джокера, Экспекто)
идут через `_kill_item()` → `knock_down()`.

**Инвариант рандома:** в любой момент существует **хотя бы одна безопасная
дорожка** — рандом не имеет права одновременно занять все 5 лейнов угрозами
(спавним угрозу только если после неё остаётся ≥1 свободный лейн в текущем «слое»).

## Библиотека сет-writing (заготовки)

Реестр именованных сценариев. Каждый — самодостаточная сцена с безопасным путём,
тегом сложности (T1–T5) и списком бэндов, где он доступен. Первые 4 — те, что
назвал дизайнер; остальные — для разнообразия.

| Сет-пис | Тир | Предметы | Суть / безопасный путь |
|---|---|---|---|
| **Ресурсная река** | T0 (вздох) | пицца | Плотная линия пицц по центру. Восстановление жира, отдых. |
| **Сэндвич** | T1 | пицца + 2 угрозы | Пицца зажата между двумя препятствиями — выбор верх/низ. |
| **Зигзаг ресурсов** | T1 | пицца | Пиццы змейкой по лейнам — дрилл на управление. |
| **Каскад бочек** | T1–T2 | бочка + пицца | Бочки каскадом по лейнам с бегущим «окном». |
| **Столбы из змей** | T2 | змея (+пицца-приз) | Вертикальные колонны змей, **безопасный лейн смещается** ±1 каждую колонну (gate). Приз-пицца в конце. |
| **Стена бомжей** | T2 | бомж (+пицца-приз) | Стена с одним бегущим проходом. |
| **Толпа бомжей** (`bum_crowd`) | T2 | бомж | Тучи бомжей **быстро** пролетают **большими кучами**, оставляя ровно **2 СОСЕДНИХ** свободных лейна; каждая туча — другая (но тоже соседняя) пара. Доступно **с фазы 1 (после 1-й минуты)**. |
| **Шахматы с камнями** | T3 | камень + пицца | Клетчатая сетка камень/пицца, чётность смещается по колонкам — читаешь рисунок и ткёшь. |
| **Диагональ** | T3 | пицца + перчатка | Диагональный проход пицц + одна перчатка сбоку. |
| **Волна перчаток** | T4 | перчатка (+пицца) | 3 колонны перчаток, **безопасный лейн смещается** каждую волну. Летально, если не угадал позицию. |
| **Волна молотовов** | T5 | молотов, огонь | Огневые стены/шахматы из молотовов; безопасные лейны чередуются. |
| **Комбо** | T5 (поздно) | сет-пис + рандом | Заготовка (напр. стена перчаток) + рандом-оверлей (дождь долларов). |

> Многие сцены уже есть в `spawner.gd` (`_t2_gate_attack` = столбы змей,
> `_t3_checkerboard` = шахматы камней, `_wave_glove_sweep` = волна перчаток,
> `_t5_molotov_*` = волна молотовов). Их можно **переиспользовать** как обработчики
> сет-writing, а не переписывать с нуля.

## 7-минутная кривая (бэнды)

7 бэндов ≈ по минуте. Скорость наследует существующий рамп (плавно 210→330).
«Рес%/Угр%» — веса рандом-пула (доля ресурсов vs простых препятствий). «Каденс СП»
— как часто директор вставляет сет-пис. «Вздох» — обязательная ресурсная река после
тяжёлой сцены.

| Мин | Бэнд | Скор. | Рандом: Рес%/Угр% | Плотн. рандома | Пул сет-writing | Каденс СП | Вздох |
|---|---|---|---|---|---|---|---|
| 0–1 | **Разминка** | 210 | 90 / 10 (только банан/бочка) | редко | Сэндвич, Зигзаг | 1 за бэнд | — |
| 1–2 | **Знакомство с угрозой** | 230 | 78 / 22 (+бомж, собака) | средне | +Каскад бочек, Столбы змей (лайт) | ~30 с | — |
| 2–3 | **Фигуры** | 255 | 68 / 32 (+камень, змея) | средне | +Шахматы камней (4 кол.), Стена бомжей | ~25 с | после Шахмат |
| 3–4 | **Первые перчатки** | 280 | 60 / 40 | плотно | +Волна перчаток (3 кол.), Диагональ | ~22 с | после каждой перчатки |
| 4–5 | **Огонь** | 300 | 55 / 45 | плотно | +Волна молотовов; чередование перчатка↔молотов | ~20 с | после молотова |
| 5–6 | **Шторм** | 320 | 50 / 50 | очень плотно | все + **Комбо** | ~16 с | каждые ~40 с |
| 6–7 | **Финал** | 330 | 45 / 55 | максимум | все + Комбо, самые тяжёлые | ~14 с | короткий |
| послед. 20 с | **Пре-босс** | 330 | — (no_pizza) | — | только перчатка↔молотов (гантлет) | без пауз | — |

**Прочтение кривой:**
- **Минуты 0–2** — учим инерции и сбору: почти чистый рандом ресурсов + пара мягких
  сцен. Экран живой, но не убивает.
- **Минуты 2–4** — вводим фигуры и первую летальную сцену (перчатки). Рандом гуще,
  появляются камни/змеи. Каждую летальную сцену закрываем ресурсной рекой (вздох).
- **Минуты 4–6** — огонь (молотов), чередование летальных сцен, комбо. Пик
  постановок, но рандом между ними даёт «дышать».
- **Минуты 6–7** — максимум плотности и частоты сцен, ведём к 20-секундному
  пре-босс гантлету (перчатка↔молотов без пиццы) → босс.

## Тюнинг и новые предметы (2026-07-01)

**Скорости.** Фон едет **вдвое медленнее** (`background.gd`: `SCROLL_SPEED`
200→100, `CITY_SCROLL_SPEED` 60→30). **ТВ и диван** синхронизированы с фоном
(`tv.gd`/`couch.gd` `SCROLL_SPEED` 200→100) — иначе ТВ «отрывался» от пола. Скорость **предметов непрерывно растёт** по
времени эпизода (`_campaign_item_speed`: 200→360 за 400 c) — заменяет фикс-скорость
фаз. Волны перчаток теперь и **со 2-й минуты** (в пуле фазы 1) с **более длинным
чарджем** (`GLOVE_CHARGE_SLOW` 0.70→0.90).

**Мутаген и золотая пицца — ультра-редкие.** Мутаген: `repeat_interval` 60→110 c,
`mutagen_chance` 0.005→0.0022 (пролетает ~раз в 2 мин). Слоты — по-прежнему 1× за
эпизод с ~4-й минуты. Новые предметы ниже — обычные, идут чаще.

**Новые предметы** (спрайты из старого проекта, в `assets/items/`):

- **Компас** (`compass_item.gd`, группа `compass`) — подобрал → **5 c реверс
  управления** (`normaldo.apply_invert`: свайп вправо двигает влево, по вертикали
  тоже наоборот). Урона нет.
- **Бомж со знаком** (`roadsign_bum.gd`) — бомж (обычное препятствие, падает с
  криком) + `road_sign.png` (небольшой, близко к бомжу, `SIGN_SCALE` 0.22),
  крутящийся с **якорем в низу палки** (`Sprite2D.offset = SIGN_CENTER − SIGN_BASE_PX`
  — так низ палки попадает в центр бомжа; вращение `_sign.rotation`, обратное).
  **Коллизия на треугольнике** (`_tri_local`, `SIGN_HIT_R`): **ломает любые предметы
  И наносит урон Нормальдо** (`normaldo.hazard_hit`, уважает неуязвимость).

**Спейсинг предметов.** `COL_SPACING` 65→**85** (≥ размера предмета ~60px, чтобы не
налезали в линиях), а **зазор на стыке единиц** директора = `_col_gap(speed)` (та же
дистанция 85px, что и внутри линии) — фикс наложения бананов на стыке тоннелей.
- **Конус** (`cone.gd`) — высокий, **3 ряда (лейна)**, с числом **5–10**. Каждый
  **тап** (по `input_event`) убавляет число; на нуле конус **сжимается на ряд** и
  число обновляется; сжатый до 1 ряда — обычное препятствие без числа.
- **Вор** (`thief.gd`) — едет по линии; **~0.5 c** наводится на ближайшую цель
  **впереди** (ресурс ИЛИ Нормальдо; сзади — никогда), при этом **поворачивается
  спрайтом в сторону цели** (`_aim_rot` + `lerp_angle`; в полёте — влево по ходу),
  затем `thief2` и **рывок**. По **ресурсу доводится** (летит прямо в него) →
  уничтожает падением. По **Нормальдо — фикс-точка**, не следует (уклоняемо). Если
  цель исчезла — всё равно прыгает в последнюю точку. За экраном умирает **только
  после того, как показался** (`_entered`).
- Спрайт **змеи** заменён на `snake2.png` (`snake.gd`, статичный вместо анимации).

Новые предметы — в рандом-пуле угроз (`_spawn_random_item`) + конус как сет-пис
(`_setpiece_cone`, фазы 1–3).

## Особые ивент-предметы (триггеры мини-игр)

Мини-игра — это **не обычный предмет**, а **особый ивент-триггер**, который
**пролетает через экран как приз-возможность**: *поймал → играешь, не поймал →
улетел*. Это именно **возможность**, не принуждение. Три триггера:

| Триггер | Мини-игра | Сложность | Длит. |
|---|---|---|---|
| **Мутаген** | [[Мини-игра — Жиробосс (мутаген)\|ЖИРОБОСС]] — гигантская голова ест всё | лёгкая / весёлая | ~короткая |
| **Пачка пиццы** | [[Мини-игра — Пицца-пати (пачка)\|Пицца-пати]] — тапаешь пачку, уворачиваешься слева | средняя | средняя |
| **Золотая пицца** | [[Мини-игра — Слоты (автомат)\|Слоты]] — свайп по колоннам, **дождь предметов сверху-вниз** | **самая сложная** | длинная (~30–35 с) |

### Принцип (что меняем)

Сейчас три контроллера **независимо** крутят свой пер-фрейм рандом
(`mutagen_chance` 0.0022, `pizza_chance`/`slots_chance` 0.004) со своими
`first_delay` (55 / 105 / 235 с) и `repeat_interval` (110 / 60 / 60 с),
гейт — общий `is_busy()`-мьютекс.
Итог: тайминг хаотичный и нескоординированный.

**Хотим:** единый **график ивент-окон под управлением директора** — примерно
**одно окно-возможность в минуту**, с плавным вводом игр по сложности.

### Частота и старт

- **≈1 ивент-окно в минуту** (всего ~5–6 за эпизод). В окне пролетает **ОДИН**
  триггер, выбранный директором.
- **Первое окно — не сразу:** грейс ~40 с на освоение управления, старт **с ~1-й
  минуты**.
- Окно ставится в **RANDOM-фазу** (между сценами), **никогда не одновременно с
  летальным сет-писом** и не пока активна другая мини-игра (мьютекс уже есть).
- После **сыгранной** мини-игры — кулдаун **~45–60 с** до следующего окна
  (переиспользуем `repeat_interval`), чтобы не спамить.
- **Последние ~40 с (пре-босс) — без мини-игр:** фокус на гантлете и боссе.

### Ввод по сложности (лёгкие → тяжёлая)

Игры открываются постепенно, самая тяжёлая — позже всех:

- **ЖИРОБОСС (мутаген)** — доступен **с ~1 мин** (самый лёгкий, знакомит с форматом).
- **Пицца-пати (пачка)** — доступна **с ~2 мин**.
- **Слоты (золотая пицца)** — доступны **только с ~4 мин** (самая сложная и длинная;
  её появление ощущается как эскалация к финалу).

### Ротация и веса

- **Не повторять одну игру два окна подряд** (разнообразие).
- Веса смещаются по времени: рано — чаще **ЖИРОБОСС**; середина — **Пицца-пати**;
  поздно — **Слоты** вероятнее (кульминация перед боссом).
- **Слоты — не чаще 1 раза за эпизод** (длинная ~30–35 с, съедает много времени
  забега); если уже сыграна — из пула выпадает.

### Примерный график окон

| Окно (~мин) | Кандидаты (вес) | Комментарий |
|---|---|---|
| ~1:00 | ЖИРОБОСС | первое знакомство, самое лёгкое |
| ~2:00 | Пицца-пати (осн.) · ЖИРОБОСС | вторая игра вводится |
| ~3:00 | ЖИРОБОСС · Пицца-пати | ротация лёгких |
| ~4:00 | **Слоты** (ввод) · Пицца-пати | первая «золотая пицца» |
| ~5:00 | любая (Слоты чаще, если ещё не была) | |
| ~6:00 | Пицца-пати · ЖИРОБОСС (Слоты, если не сыграна) | предфинальная |
| 6:20–7:00 | — | пре-босс, без мини-игр |

> Точное окно «плавает» ±10–15 с, чтобы не быть строго по метроному, но
> ощущение «примерно раз в минуту есть шанс сыграть» сохраняется.

### Технические зацепки

- Вынести решение о триггере из трёх независимых пер-фрейм рандомов в **директора**
  (общий scheduler): таблица `EP1_EVENT_WINDOWS` (минута, пул игр, веса, «не два
  подряд», «Слоты 1×»), директор в RANDOM-фазе открывает окно и просит нужный
  контроллер выпустить триггер (напр. `FatBoss.spawn_trigger()` /
  `PizzaParty.spawn_trigger()` / `SlotsGame.spawn_trigger()`) вместо их
  собственного `randf() < chance`.
- Мягкий вариант без большого рефактора: оставить `_arm_timer`/`is_busy`, но
  eligibility (`first_delay`, доступность Слотов ≥4 мин, «не два подряд»,
  «Слоты 1×») и кулдаун выставлять **из директора по бэндам**, а сами `*_chance`
  свести к «в открытом окне — гарантированный пролёт триггера».

## Инварианты (правила честности)

1. **Всегда есть безопасный путь** — и в рандоме, и в каждой сцене (сдвигающийся
   свободный лейн).
2. **Вздох после летального** — после волны перчаток/молотовов обязательно
   ресурсная река или чистое рандом-окно (восстановление жира, психологический
   отдых).
3. **Летальное — только читаемыми сценами**, никогда случайным шумом. У перчатки/
   молотова есть телеграф (замах/warning-овал) — рандом их не подаёт.
4. **Ресурсный бюджет** — за первые 3–4 минуты средний игрок должен успеть набрать
   жир 2–3 (см. [[Система толщины]]): рандом ресурсов + ресурсные реки это
   обеспечивают. Жир = player-driven ось сложности (тяжелее управление).
5. **Не пересекаемся с мини-играми** — триггеры мини-игр идут по **графику
   ивент-окон** директора (см. раздел «Особые ивент-предметы» выше): ~1 окно в
   минуту, ввод по сложности, Слоты — с 4-й минуты. Директор **не запускает
   летальную сцену** во время ивент-окна и пока `is_busy()` мини-игры активна
   (мьютекс уже есть).
6. **Один пик за раз** — комбо (сцена+оверлей) только с 5-й минуты; до этого сцены
   не накладываются друг на друга.

## Технические зацепки (для реализации позже)

Ложится на существующий `scripts/spawner.gd` без слома скорости-по-фазам:

- **`EP1_BANDS`** — таблица бэндов (скорость, веса рандом-пула, плотность,
  eligible-сет-writing, каденс, вздох). По времени `_elapsed` выбираем бэнд.
- **`_director_loop()`** — заменяет `_run_campaign_pattern`; крутит
  RANDOM-окна и SET-PIECE-окна по каденсу бэнда.
- **`_random_window(dur)`** — цикл `_spawn_random_item()` с интервалом плотности;
  следит за инвариантом «≥1 свободный лейн».
- **`_spawn_random_item(band)`** — взвешенный выбор типа из пула бэнда + выбор лейна.
- **`SET_PIECES`** — реестр `{ id, tier, min_band, weight, fn }`; `fn` —
  переиспользуемые обработчики (частью уже есть: `_t2_gate_attack`,
  `_t3_checkerboard`, `_wave_glove_sweep`, `_t5_molotov_*`).
- **Вздох** — переиспользовать `_run_calm_wave`/ресурсную линию.
- **Пре-босс** — оставить как есть (`_campaign_pre_boss_pattern`, no_pizza,
  перчатка↔молотов), директор просто передаёт управление ему на последних 20 с.

Скорость-по-фазам (`CAMPAIGN_PHASES`) можно оставить как отдельную ось — директор
читает текущую скорость бэнда, но сам управляет **содержимым**, а не темпом.
